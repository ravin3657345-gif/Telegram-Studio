Переезд Telegram-бота на Supabase: работайте без VPN

Пошаговая инструкция, как перенести своего Telegram-бота в облако Supabase — по той же схеме, по которой мы перенесли наш sales-bot. Бот отвечает без VPN и без включённого компьютера.

✅ Без VPN ✅ Без включённого ПК 💸 Бесплатный тариф 🔒 Токены зашифрованы
Вариант А — релейБот остаётся у вас, работает через пересыльщик на Supabase. 15 минут, подходит для любого языка.
Вариант Б — переездБот целиком живёт на Supabase (как sales-bot). 1–2 часа, компьютер можно выключать.
Данные — в облакеЖурнал, файлы и file_id-кеш — в Postgres и Storage. Отложенные задачи — через pg_cron.
БезопасноТокен — в зашифрованных секретах Supabase, вебхук защищён секретом от чужих вызовов.

01 · Схема

Как это работает

Блокировка в РФ работает так: провайдер обрывает соединение по IP-адресу api.telegram.org — любой запрос из домашней сети к этому адресу умирает. А вот к адресам Supabase (облако за границей, обёрнутое в Cloudflare) достучаться можно.

Решение — поменять адрес, по которому бот ходит в Telegram, с заблокированного на доступный:

БЕЗ РЕШЕНИЯ                                С РЕШЕНИЕМ
                                            ┌─────────────────────────────┐
┌──────────┐                               │        SUPABASE (облако)      │
│  Ваш бот  │ ── запрос ── ✂️ ❌              │                             │
│(ПК/сервер)│      api.telegram.org         │  ┌───────────────────────┐  │
└──────────┘                               │  │  Edge Function         │  │
                                           │  │  (ваш бот / релей)     │  │
                                           │  └──────────┬────────────┘  │
                                           │             │  запрос       │
                                           │             ▼               │
                                           │  ┌───────────────────────┐  │
                                           │  │    api.telegram.org   │  │
                                           │  └───────────────────────┘  │
                                           └─────────────────────────────┘
Вариант А15 минут

Бот остаётся на вашей машине, а запросы к Telegram идут через релей — маленькую функцию-пересыльщик на Supabase.

Вариант Б1–2 часа

Весь бот переезжает в Supabase как вебхук-функция — как наш sales-bot. Компьютер можно выключать.

03 · Вариант А

Релей: бот остаётся у вас Бот продолжает жить на вашей машине, но вместо api.telegram.org ходит в Telegram через функцию-пересыльщик на вашем Supabase. Код бота не переписывается — меняется одна строка (адрес API).

  1. Создайте проект Supabase

    Зайдите на supabase.com → Start your project. Введите название и пароль от базы данных, выберите регион (любой кроме России — например Frankfurt). Дождитесь создания.

    На странице Project Settings → API скопируйте Project URL вида https://abcdefghijklmnopqrst.supabase.co. Кусок abcdefghijklmnopqrst — это Project Ref, он понадобится дальше.

  2. Разверните функцию-релей

    Установите CLI и подключитесь к проекту:

    терминал — установкаbash
    
          
    терминал — инициализация и подключениеbash
    
          
    Создайте функцию:
    
          
    терминалbash
    
          
    Замените содержимое supabase/functions/tg-relay/index.ts на это:
    
          
    supabase/functions/tg-relay/index.tsts
    
          
    Выключите проверку JWT — добавьте в конец файла supabase/config.toml:
    
          
    supabase/config.tomltoml
    
          
    Задеплойте и проверьте:
    
          
    терминал — деплой и проверкаbash
    
          
    Релей работает, если в ответе пришло имя вашего бота ("username": "..."). 🎉 Проверка ходит на ваш Supabase (доступен), а уже Supabase ходит в Telegram (тоже доступен — его сервера за границей), поэтому команда сработает даже при полной блокировке.

04 · Вариант Б
Полный переезд: бот живёт на Supabase Бот переезжает в облако целиком — как наш sales-bot. Теперь это вебхук-функция: Telegram сам присылает апдейты на адрес функции, функция обрабатывает и отвечает. Ваш компьютер больше не нужен.

      
Важное ограничение: Supabase-функции выполняются на Deno/TypeScript. Если ваш бот написан на Node.js — переезд почти безболезненный. Если на Python/Go/PHP — потребуется переписывание; для таких ботов используйте Вариант А.


      
    
        
  1. 
          
    Создайте проект и подготовьте CLI
    
          
    Как в Варианте А: создайте проект Supabase, установите CLI, затем:
    
          
    терминалbash
    
        
    2. 
        
  2. 
          
    Создайте функцию-бота
    
          
    терминалbash

    supabase/functions/bot/index.tsts
    
          
    Это каркас. Внутрь вставляете свою логику — точно так же, как она была в обычном боте: if (message.text === …) / обработка callback-кнопок (update.callback_query) и т.д.
    
        
    3. 
        
  3. 
          
    Настройте конфиг и секреты
    
          
    Добавьте в конец supabase/config.toml:

05 · Дополнительно
База данных, файлы, отложенные задачи Всё, что наш sales-bot хранил в файлах и CSV, мы перенесли в Postgres и Storage Supabase. Вам пригодятся те же приёмы.

фрагмент: запись в журналts

🖼 Медиа и кеш file_id

      
Отправка фото из функции:

      
фрагмент: sendPhoto по file_idts

      
Первую загрузку файла сделайте один раз (например, скриптом при деплое), сохраните file_id в таблицу и переиспользуйте — это и быстро, и дёшево. Наш sales-bot именно так раздаёт установщики: загрузил один раз, раздаёт по file_id.


      
⏰ Отложенные задачи (рассылки, напоминания)

      
Вебхук-функция вызывается только по апдейту, поэтому «будильники» делаются отдельно: создайте функцию-задачу и вызывайте её по расписанию через pg_cron (в SQL-редакторе) — она раз в N минут дёргает вашу функцию HTTP-запросом.

08 · FAQ
Вопросы и ответы


      
Это вообще легально?
Да. Telegram Bot API официально разрешает кастомные API-серверы (на этом построена вся экосистема локальных telegram-bot-api серверов и прокси). Вы не нарушаете правила — вы просто ходите к API другим адресом.


      
Мой бот на Python. Что делать?
Для Python бот остаётся у вас, но работает через релей (Вариант А) — это покрывает 99% проблемы. Полный переезд в облако (Вариант Б) поддерживает только Node.js/TypeScript, потому что Supabase-функции — это Deno.


      
Сколько это стоит?
Бесплатно: 500 000 вызовов функций/мес, 500 МБ БД, 1 ГБ файлов, 5 ГБ трафика. Для обычного бота хватает. Если бот очень активный — Pro ($25/мес) поднимает до 2 млн вызовов.


      
Почему поллинг дороже вебхука?
Поллинг опрашивает сервер каждые 1–2 секунды — это сотни тысяч вызовов в месяц. Вебхук вызывается только когда приходит сообщение. Поэтому в Варианте Б всегда используйте вебхук.


      
Мой бот отправляет фото — пройдёт?
Из Supabase — да, запросы идут с заграничных серверов, блокировки нет. Через релей (Вариант А) крупные файлы могут не пройти — тогда отправляйте по file_id.


      
Можно ли откатиться?
Да. Удалите вебхук (deleteWebhook) — бот вернётся к работе на вашей машине как раньше. Никаких данных в Supabase это не трогает.


      
Что будет, если не пользоваться ботом неделю?
Бесплатный проект Supabase ставится на паузу после 7 дней неактивности. Первое сообщение боту «разбудит» его автоматически — просто первая обработка может занять на пару секунд дольше.

    


    

      
Инструкция построена на живом опыте: наш sales-bot перенесён на Supabase (вебхук-функция, журнал в Postgres, раздача файлов по file_id) — он работает из России без VPN и без включённого компьютера продавца.
