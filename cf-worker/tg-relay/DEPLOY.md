# Развёртывание CF Worker-релея Telegram Bot API

> **Статус: ЗАДЕПЛОЕНО 2026-09-09.** Воркер `tg-relay` развёрнут через
> REST API, секрет `RELAY_KEY` поставлен, workers.dev-роут включён.
> Адрес в `client.rs` вписан. Инструкция ниже осталась для справки —
> если понадобится перевыпустить ключ или перезадеплоить.

Резервный путь №2 для публикации без VPN (исходник — `worker.js` рядом).
Результат: адрес вида `https://tg-relay.<ваш-поддомен>.workers.dev/tg-relay`,
который транзитит запросы в `api.telegram.org`. Файлы до 100 МБ идут одним
запросом — без 20-КБ чанков, как на Supabase-пути.

При обновлении ключа: `wrangler secret put RELAY_KEY` (новое значение) + то
же значение в `CF_RELAY_KEY` в `client.rs` + пересборка. Ключ хранится в
`.freebuff/cf-relay-key.txt` (не коммитить).

## Шаг 1. Установить wrangler (CLI Cloudflare)

```bash
npm install -g wrangler
wrangler login
```

Откроется браузер — войдите в тот аккаунт Cloudflare, где живёт ваш
поддомен `ravin3657345.workers.dev`.

## Шаг 2. Задеплоить воркер

В папке `cf-worker/tg-relay/`:

```bash
wrangler deploy
```

В конце вывода будет адрес вида
`https://tg-relay.ravin3657345.workers.dev` — запишите его.

Проверка, что воркер жив (должен ответить 403 — без ключа это норма):

```bash
curl https://tg-relay.ravin3657345.workers.dev/tg-relay/bot123:test/getMe
```

## Шаг 3. Поставить секретный ключ

Сгенерируйте случайный ключ (пример для PowerShell):

```powershell
$bytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
[Convert]::ToBase64String($bytes)
```

Поставьте его как секрет воркера (вставьте значение, когда спросит):

```bash
wrangler secret put RELAY_KEY
```

## Шаг 4. Вписать адрес и ключ в исходник приложения

В `src-tauri/src/telegram/client.rs` замените два плейсхолдера:

```rust
const CF_RELAY_BASE: &str = "https://tg-relay.<ВАШ-ПОДДОМЕН>.workers.dev/tg-relay";
const CF_RELAY_KEY: &str = "<СГЕНЕРИРОВАННЫЙ-КЛЮЧ>";
```

на реальные значения из шагов 2–3, например:

```rust
const CF_RELAY_BASE: &str = "https://tg-relay.ravin3657345.workers.dev/tg-relay";
const CF_RELAY_KEY: &str = "AbC123...your-key...xYz=";
```

Пока стоит плейсхолдер, CF-уровень автоматически пропускается и поведение
точно такое, как до его появления — ничего не сломается.

Пересоберите приложение (`npm run tauri:dev` или релиз-сборка).

## Шаг 5. Живой тест (важно!)

Тестировать из сети **без VPN** (или хотя бы с той, где воспроизводилась
блокировка):

1. Текст: опубликуйте пост без картинок — при прямом подключении он
   уйдёт напрямую, CF-уровень не задействуется. Чтобы принудительно
   проверить релей, можно временно заблокировать доступ к
   `api.telegram.org` (или отключить сеть на секунду публикации).
2. Фото (~1–5 МБ): опубликуйте пост с фото. В логах (Debug) ищите
   строки `[tg-cf]` — они показывают, что пошло через CF-уровень, и
   статус ответа.
3. Видео (~5 МБ): главный тест — именно большие файлы раньше шли
   ненадёжно. Если уходит одним запросом — ограничение закрыто.

## Если workers.dev заблокирован у провайдера

Привяжите собственный домен (любой купленный домен, добавленный в ваш
аккаунт Cloudflare — бесплатно):

1. Cloudflare Dashboard → Workers & Pages → `tg-relay` → Settings →
   Domains & Routes → Add → Custom domain (например, `tg-relay.вашдомен.ru`).
2. DNS-запись создастся сама; TLS — тоже.
3. В `client.rs` поменяйте `CF_RELAY_BASE` на
   `https://tg-relay.вашдомен.ru/tg-relay` и пересоберите.

Свой домен за CDN Cloudflare для провайдера выглядит как обычный сайт и
блокируется значительно неохотнее, чем весь `*.workers.dev` разом.

## Безопасность

- `RELAY_KEY` — не токен бота; утеча компрометирует только транзит,
  меняется одной командой `wrangler secret put` (+ пересборка приложения
  с новым значением в `CF_RELAY_KEY`).
- Токены ботов через воркер проходят только внутри пути
  `/bot<токен>/<метод>` — как и в прямом подключении; воркер их не логирует
  и никуда, кроме `api.telegram.org`, не пересылает.
